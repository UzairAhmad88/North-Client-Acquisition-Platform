# Organizational Learning & Continuous Improvement

## 1. Empirical Evidence Grounding

Every discovered organizational insight (`BusinessInsight`) must contain quantitative audit-proof evidence records (`BusinessInsightEvidence`):

- Source pattern classification (e.g., `ESTIMATION_VARIANCE`, `LEAD_SCORE_CALIBRATION`, `REQUIREMENTS_AMBIGUITY_CORRELATION`).
- Minimum sample size threshold: $n \ge 5$. Small samples return `INSUFFICIENT_DATA` rather than fabricated inferences.
- Explicit baseline vs observed values and calculated variance percentages.
- Confidence attribution: `HIGH` ($n \ge 20$), `MEDIUM` ($n \ge 10$), `LOW` ($n \ge 5$).

---

## 2. Human Recommendation Review Lifecycle

Recommendations (`BusinessRecommendation`) generated by the Learning Engine require explicit human decision:

```text
Discovery Insight Generated
        ↓
Recommendation Formulated (Reason + Benefit + Tradeoff)
        ↓
Status: PENDING_APPROVAL
        ↓
Human Review:
├── APPROVE  → Human accepts policy/process suggestion
├── REJECT   → Human rejects suggestion with reason
└── IMPLEMENT → Change enacted via versioned configuration
```

Under no circumstances does an insight or recommendation automatically alter runtime pricing, scoring coefficients, or contract terms.

---

## 3. Continuous Experiment Framework

Hypotheses are formulated with formal testable targets:
- Baseline metric value (e.g., baseline 3.0 scope changes/project).
- Target metric value (e.g., target 1.0 scope change/project).
- Target trial sample count (e.g., $n = 10$ projects).
- Statistical progress evaluation via `HypothesisEngine`.
